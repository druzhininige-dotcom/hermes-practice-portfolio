# 04 — Lid_AI: классификация лидов из Telegram-чатов

**Задача.** В чатах Дальнего Востока (Владивосток, Хабаровск, Уссурийск) люди пишут:
«нужен шкаф», «привезти партию из Китая», «ищу маркетплейс-специалиста», «надо ИИ-агента».
Сообщений — сотни в день. Нужно: **не пропустить лид, не спамить в группу, разложить по
профилям услуг** (мебель / маркетплейсы / логистика / ИИ-агенты) и прислать карточку
менеджеру.

**Решение.** Автономный сервис на Python: слушает чаты (Telethon) → предфильтр (ключевые
слова, стоп-слова) → LLM (OpenAI-совместимый) → **детерминированная арифметика балла** →
SQLite → карточка в Telegram-группе «ЛИДЫ» в топике профиля.

---

## Как считается балл — арифметика, а не «модель решила»

Модель отдаёт **только ярлыки** по четырём осям. Балл считает код — детерминированно.

```
score = 10 × (0.40·intent + 0.30·domain + 0.20·specificity + 0.10·urgency)
```

| Ось | 1.0 | 0.5 | 0 |
|---|---|---|---|
| **intent** | прямо ищет исполнителя/цену/контакт | интересуется, сравнивает | рассуждение |
| **domain** | ровно услуги профиля | смежное/часть услуги | не наше |
| **specificity** | 2–3 параметра (габарит, бюджет, срок) | 1 параметр | общими словами |
| **urgency** | срочно / дедлайн | в ближайшее время | без срока |

**Правила отсева (в `scorer.py`):**
- Автор сам предлагает услугу или ищет работу → `is_lead=false`, балл ≤ 2.
- Автор сам предлагает услугу или ищет работу → `is_lead=false`, балл ограничен `NEGATIVE_CAP = 2.0`.
- Лучший профиль ниже порога (`threshold`, по умолчанию 5.0) → `rejected_auto`; второй показывается при `best.score − s.score ≤ 2.5` (`SECONDARY_MAX_GAP`).

## Модули

```
app/
  main.py            цикл: collector → pipeline → notifier
  collector/
    listener.py      Telethon: слушает чаты, отдаёт нормализованные сообщения
  pipeline/
    prefilter.py     ключевые слова / стоп-слова / правила «не лид» (быстро, без LLM)
    llm.py           вызов модели, парсинг JSON-ответа
    prompt.py        системные промты по профилям
    scorer.py        judgement_score(), Ranking, NEGATIVE_CAP
    processor.py     связка: prefilter → llm → scorer
  notifier/
    formatter.py     карточка лида → Markdown для Telegram
    sender.py        отправка в группу/топик
  db.py              SQLite: profiles, chats, leads, scores, events, outbox, llm_calls
  schemas.py         Pydantic-схемы: LLMAnswer, ProfileJudgement, WEIGHTS, LEVEL_VALUE
  profiles.py        загрузка profiles/*.yaml → БД
scripts/
  calibrate.py       подбор весов на размеченных данных
  verify_stage1.py   прогон этапа 1, отчёт стабильности
```

## Профили (YAML, синхронизируются в БД)

| slug | Название | Тег | Порог |
|---|---|---|---|
| `mebel` | Смета и проект мебели | `#мебель` | 5.0 |
| `mp` | Специалист по маркетплейсам | `#маркетплейсы` | 5.0 |
| `log` | Логистика и подбор товара из Китая | `#логистика` | 5.0 |
| `ai` | ИИ-агенты и автоматизация | `#ии` | 5.0 |

Профиль = «клиент» в мультиклиентности: свои ключевые слова, стоп-слова, правила «не лид»,
порог, группа и **топик** Telegram (`tg_topic_id`). Если топик задан — карточка уходит туда,
иначе — тег в первой строке.

## Что показательно

- **LLM только за ярлыками**, балл — формула в коде. Модель на границе порога может
  «дрожать», арифметика — нет.
- **Предфильтр отсекает 80 % шума** без вызова модели (ключевые/стоп-слова).
- **Outbox-паттерн** (`db.py`: таблица `outbox`) — если Telegram недоступен, карточка не
  теряется, уйдёт при следующем цикле.
- **Мультипрофильный scoring** — одно сообщение может дать два лида (основной + второй),
  если второй прошёл свой порог и близок к первому.
