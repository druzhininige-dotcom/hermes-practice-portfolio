# Lid_AI — лиды из Telegram-чатов по 4 профилям

Сервис слушает заданные Telegram-чаты, для каждого сообщения оценивает **все четыре
профиля услуг**, выбирает лучший (и второй, если оценки близки), складывает всё в БД
и присылает карточку в группу «ЛИДЫ» — в топик профиля или с тегом.

Этап 1 (MVP) готов: сбор → предфильтр → LLM → скорер → БД → карточка.

---

## Профили

| slug | Название | Тег | Порог |
|---|---|---|---|
| `mebel` | Смета и проект мебели | `#мебель` | 6 |
| `mp` | Специалист по маркетплейсам | `#маркетплейсы` | 6 |
| `log` | Логистика и подбор товара из Китая | `#логистика` | 6 |
| `ai` | ИИ-агенты и автоматизация | `#ии` | 6 |

Профиль — это «клиент» в терминах мультиклиентности. У каждого свои:
описание услуг (идёт в промт), ключевые слова, стоп-слова, правила «не лид»,
порог, группа и **топик** Telegram. Всё лежит в `profiles/*.yaml` и синхронизируется в БД.

Если у профиля задан `tg_topic_id` — карточка уходит в его топик группы.
Если топиков нет — тег (`#мебель` и т.д.) в первой строке карточки всё равно различает профили.

---

## Как считается балл

Модель отдаёт **только ярлыки**, балл считает код — детерминирована арифметика,
ярлыки ставит модель и на границе порога могут колебаться:

```
score = 10 × (0.40·intent + 0.30·domain + 0.20·specificity + 0.10·urgency)
```

| Ось | 1.0 | 0.5 | 0 |
|---|---|---|---|
| intent | прямо ищет исполнителя/цену/контакт | интересуется, сравнивает | рассуждение |
| domain | ровно наши услуги профиля | смежное/часть услуги | не наше |
| specificity | 2–3 параметра | 1 параметр | общими словами |
| urgency | срочно/дедлайн | в ближайшее время | без срока |

Правила:
- автор **сам предлагает услугу** или **ищет работу** → `is_lead=false`, балл ≤ 2;
- `lead_type = discussion/none` → не запрос, балл ≤ 2;
- лучший профиль ниже своего порога → `rejected_auto` (в БД, но в группу не идёт);
- второй профиль показывается, если он прошёл свой порог и отстаёт не больше чем на
  `SECONDARY_MAX_GAP` (по умолчанию 3.0).

## Установка

```bash
# Python 3.11+, зависимости
uv venv C:\Users\<user>\.venvs\lid_ai
uv pip install --python C:\Users\<user>\.venvs\lid_ai\Scripts\python.exe -e ".[dev]"
```

Скопируйте `.env.example` → `.env` и заполните. Минимум для работы:

```
TG_API_ID=…            # my.telegram.org → API development tools
TG_API_HASH=…
TG_PHONE=+79…          # номер аккаунта-сборщика (отдельный, не основной)
BOT_TOKEN=…            # бот, который пишет в группу ЛИДЫ
LEADS_GROUP_ID=-100…   # id группы ЛИДЫ
LLM_API_KEY=…          # ключ DeepSeek (или другого OpenAI-совместимого провайдера)
DRY_RUN=true           # сначала прогон без отправки в Telegram
```

Первый вход в аккаунт-сборщик (одноразово, нужен код из Telegram):

```bash
python scripts/login_telethon.py
```

Аккаунт должен **уже состоять** в чатах, которые слушаем: в приватные чаты он сам не войдёт.

## Запуск

```bash
python scripts/seed_profiles.py                       # профили из YAML → БД
python scripts/seed_profiles.py --chat -1001234567890 --profiles mebel,mp --title "Мебельщики"
python scripts/calibrate.py                           # проверка на тестовом наборе (реальный LLM)
python -m app.main                                    # боевой запуск
```

Проверить одно сообщение и увидеть карточку:

```bash
python scripts/classify_text.py "нужна смета на кухню 3,6 м, кто посчитает?"
```

`DRY_RUN=true` — карточка пишется в лог, в Telegram не уходит. Для боевого режима
поставьте `DRY_RUN=false`.

## База

SQLite (`data/lid_ai.db`), схема создаётся автоматически.

```
profiles            клиент: промт-поля, ключевые, порог, группа/топик
chats               чаты Telegram
profile_chats       какой профиль слушает какой чат (мультиклиентность)
seen_messages       дедуп: (chat_id, message_id) + hash текста
leads               profile_id = лучший профиль, score, статус, notify_state
lead_profile_scores оценки ВСЕХ профилей по каждому сообщению (is_best/is_secondary)
lead_events         аудит смены статусов (этап 2)
outbox              очередь отправки, идемпотентность
llm_calls           токены/деньги на каждый вызов, дневной бюджет
```

Ключевое: `UNIQUE(chat_id, message_id)` в `leads` — одно сообщение даёт ровно одну
карточку, реконнект Telethon не создаёт дублей.

## Тесты

```bash
python -m pytest -q             # 95 тестов без сети (+ живые с ключом модели)
python -m pytest -q -m "not live"   # только быстрые, без трат
python -m pytest -m live -v     # живой прогон (нужен LLM_API_KEY)
```

Тестовый набор `tests/cases.yaml`: по 2 положительных и 2 отрицательных на каждый
профиль + 2 перекрёстных («бот для отзывов Ozon» → `ai` и `mp`; «карточки на Ozon +
партия из Китая» → `mp` и `log`).

## Стоимость

Один вызов на сообщение (все профили сразу). DeepSeek: ~2.5–3 тыс. токенов промта +
~300 токенов ответа → около **$0.001 на сообщение**; 300 сообщений/день после
предфильтра ≈ **$0.3/день** при цене $0.27/$1.10 за 1M. Точные цены задаются
в `.env` (`LLM_PRICE_IN_PER_1M`, `LLM_PRICE_OUT_PER_1M`), дневной лимит —
`LLM_DAILY_BUDGET_USD`.

## Windows-грабли (проверено на этой машине)

- **venv вне кириллического пути.** `uv venv` в `D:\файлы Гермес\...` может не создать
  окружение. Делайте `uv venv C:\Users\<user>\.venvs\lid_ai` и указывайте
  `--python C:\...\Scripts\python.exe` при установке пакетов.
- **Telethon пишет `Failed to load SSL library`** — на Windows нет libssl, Telethon
  переходит на медленное Python-шифрование. Лечится `uv pip install cryptg`
  (не обязательно, но соединение будет быстрее).
- **Кириллица в путях** проекту не мешает (все пути через `pathlib`), но логи и БД
  лучше держать внутри папки проекта: `data/`, `logs/`.

## Ограничения (честно)

1. **Telethon — пользовательский аккаунт.** Массовое чтение чатов противоречит ToS
   Telegram, аккаунт может получить ограничения. Смягчение: отдельный аккаунт,
   только чтение, без рассылок, разумное число чатов. Гарантий нет.
2. **Вход интерактивный** — нужен `api_id/api_hash` и код из Telegram.
3. **Порог и промт калибруются по факту.** Первые 2 недели смотрите, что приходит,
   правьте `not_lead` в YAML и порог.
4. **Риск-профиль:** если чат спамит, предфильтр отсекает большую часть, но бюджет
   всё равно ограничен (`LLM_DAILY_BUDGET_USD`).
5. **Этап 2** (кнопки статусов, ретраи outbox, healthcheck) и **этап 3** (дашборд)
   ещё не сделаны.
