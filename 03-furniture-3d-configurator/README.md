# 03 — Параметрический 3D-конструктор мебели с расчётом сметы

**Задача.** Клиент задаёт параметры кухни/шкафа (габариты, секции, фасады, столешницу, фартук)
→ получает 3D-сцену в браузере и **готовый расчёт раскроя + смету по прайсу цеха**.
Раньше расчёт делали вручную: замер → PRO100 → ручная смета → картинка. Нужно убрать ручные
переходы и «зашитые» размеры.

**Решение.** Единый пайплайн: параметры → модель (`model/`) → Three.js-сцена + раскрой +
смета. Геометрия **только** в Python, JavaScript не знает размеров мебели.

---

## Архитектура

```
model/
  построить.py       ВХОД: изделие → дерево деталей (корпус + фасады + столешница + фартук)
  правила.py         Два класса правил: «припуск детали» и «расстановка»
  изделие.py         Схемы (Pydantic): изделие, секция, деталь, предупреждение
  calculate.py       РАСЧЁТ: дерево деталей → раскрой (shelf-packing) + смета (9 статей)
  сборка.py          Фурнитура, крепёж, автоматический подбор по типам деталей
  визуал/            генераторы GLTF/JSON для Three.js (k3d.py)
```

### Жёсткие правила (видны в коде)

1. **Геометрия — только `построить()`.** В `k3d.py` и JS нет ни миллиметра размеров мебели.
2. **Деньги — только формулами из прайса** «Для ИИ стоимость.xlsx».
3. **Неподтверждённое = 0 + предупреждение.** В `правила.py` каждое число имеет флаг
   `подтверждено: bool`. `False` → значение не применяется в расчёте, попадает в
   `изделие.предупреждения` с пометкой `УТОЧНИТЬ`.
4. **Тесты не править «чтобы прошли».** Смена ожидания — в отчёте: было / стало / почему.
5. **Смета и раскрой — детерминированно.** Нейросеть — только картинка (Pollinations.ai).

### Два класса правил (`правила.py`)

| Класс | Влияет на | `подтверждено=False` → |
|---|---|---|
| **припуск детали** | раскрой, смета, геометрия | значение = 0, предупреждение |
| **расстановка** | только позиции деталей (x/y/z) | значение = предложенное, пометка «ПРЕДВАРИТЕЛЬНО» |

Это разделение позволяет двигать фасад визуально (расстановка), не ломая раскрой и смету
(припуск) до ответа мастера.

### Расчёт (`calculate.py`)

Вход: изделие (дерево деталей). Выход:

```
раскрой:
  детали[]        — каждая: размер, материал, кромка (стороны + п.м), кол-во
  по_материалам[] — свод: м², п.м кромки, штук
  листы[]         — карта раскроя ЛДСП (shelf-packing)
смета:
  статьи[]        — корпус, кромка, фасады, фурнитура, работа, спец. для фабрики
  себестоимость, наценка, итого
  непосчитанное[] — статьи без подтверждённых чисел/цен
```

Лист по материалам считается как **разложение на листы** (shelf-packing), а не «площадь/площадь листа».

### API и 3D

- `app.py` — HTTP-сервер на `http.server` (ThreadingHTTPServer), порт 8090.
- `GET /сцена3д` — возвращает JSON для Three.js, debounce 300 мс + кэш.
- Клиентская часть: камера `near 0.05 / far 100`, `min/maxDistance` от габарита,
  клик по детали → размерные линии, «Открыть двери» + ручки.

## Что показательно

- **Разделение ответственности**: Python = геометрия + деньги, JS = только рендер.
- **Правила с флагами подтверждения** — механика «не أعرف точно, но могу предложить» вместо
  однозначного угадывания.
- **Тесты как контрольная сумма**: `проверка_3д.py` (69 проверок, код 0) и
  `проверка_модели.py` (габарит сходится, состав — ждём Костю).

## Ограничения

Параметры фартука (550 мм), высоты кухни, текстуры (дуб/венге/титан), размеры ручек,
цены покраски МДФ — ждут подтверждения заказчика. В коде это видно: `подтверждено=False`.
