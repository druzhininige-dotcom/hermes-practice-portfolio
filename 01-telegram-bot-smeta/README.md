# 01 — Telegram-бот смет для мебельного цеха

**Задача.** Конструктор цеха присылает выгрузку раскроя из PRO100 (текстовый файл с деталями).
Раньше смета на 9 листов собиралась вручную в Excel: 40–60 минут на изделие, и любая опечатка
в цене уезжала заказчику. Нужно было получить готовый файл прямо из мессенджера.

**Решение.** Бот `@MebelSmetaBot` принимает `.txt` из PRO100 (одним или двумя файлами — корпус и
фасады отдельно), считает смету и возвращает готовый `.xlsx` по шаблону цеха.

---

## Как устроено

```
bot.py            приём файла, диалог, отправка результата
engine/
  parse_cut.py    парсер выгрузки PRO100 → список деталей
  estimate.py     классификация деталей, цены, расчёт, сборка xlsx
  make_smeta.py   обвязка вызова
```

### Парсинг раскроя

Выгрузка PRO100 — TSV с фиксированным порядком колонок:

| Колонка | Смысл |
|---|---|
| A | длина, мм |
| B | толщина, мм |
| C | ширина, мм |
| D | количество |
| E | материал (путь вида `ДСП\ДСП\Kronospan\Дуб…`) |

Отдельная строка вида `d6` — погонаж, а не деталь. Парсер это различает и не превращает
погонные метры в площадь.

### Классификация детали

Правило жёсткое, без «угадывания по одной толщине»:

1. **толщина** — 4 мм → задняя стенка; ≥ 30 мм → столешница;
2. **группа** (колонка 0 выгрузки) — корпус, фасад, прочее;
3. **материал** — уточнение внутри группы.

Порядок именно такой, потому что одна и та же толщина 16 мм бывает и у корпуса, и у полки.

### Расчёт

- Лист ЛДСП — **целыми листами**, размер берётся по производителю плиты:
  Kronospan / ТомлесДрев / Lamarty / Увадрев / Nordeco — 2750×1830, Egger — 2800×2070.
- Распил — отдельной строкой, не «зашит» в стоимость листа.
- Кромка — двумя строками (материал + наклейка), длина = периметр торцов × `DOLYA_EDGE` (0.6).
- Цены — **только** из прайса цеха по точному имени позиции.
- Нет цены в прайсе → строка помечается `УТОЧНИТЬ` и **не** превращается в число.

### Девять листов на выходе

`Корпус-ЛДСП` · `Задние стенки 4мм` · `Фасады` · `Столешница и панель` · `Фурнитура` ·
`Работа` · `Спец.для фабрики` · `Карта раскроя` · `Допущения`

Лист **«Допущения»** — принципиальный: каждое принятое решение (доля кромления, какая деталь
признана фасадом, откуда взята цена) выводится явным списком. Смету можно проверить, не читая код.

---

## Что показательно в этом проекте

- **Нейросети в расчёте нет вообще.** Смета — арифметика. Модель, которая «примерно» считает
  деньги, дороже, чем её отсутствие.
- **Карта раскроя** — shelf-packing: детали укладываются на лист полками, считается реальное
  число листов, а не площадь «в лоб».
- **Отказ от неопределённости**: `УТОЧНИТЬ` как штатное состояние системы, а не ошибка.

## Ограничения, о которых знаю

Состав модулей, петли и техника из выгрузки PRO100 не выводятся — бот спрашивает их отдельно.
Это ограничение исходных данных, а не логики, и обходится диалогом.
