# Артём Дружинин — ИИ-агенты и автоматизация для реального бизнеса

Проектирую и пишу рабочие системы, которые считают деньги, а не демонстрируют «магию нейросетей».
Четыре направления: **корпусная мебель**, **маркетплейсы (WB / Ozon)**, **импорт из Китая**,
**локальные ИИ-агенты на своём железе**.

Всё в этом репозитории — не учебные примеры, а код, который работал (или работает) на реальных задачах:
сметы уходили заказчикам, боты отвечали покупателям, отчёты читали владельцы магазинов.

> English summary: production-oriented Python automation & LLM agent work — deterministic money
> math (no LLM where arithmetic is needed), Telegram bots, marketplace analytics, a parametric
> 3D furniture configurator, and a lead-classification pipeline with tests.

## Как я работаю с ИИ — три правила из практики

Это не декларации, они видны в коде каждого проекта.

**1. Деньги считает код, а не модель.**
В смете, раскрое и себестоимости нет ни одного вызова LLM. Нейросеть — только там, где нужна
семантика (распознать деталь по описанию, понять, лид это или нет). Причина простая: модель,
которая «немного ошиблась» в сумме, обходится дороже, чем её отсутствие.
Пример: [`calculate.py`](03-furniture-3d-configurator/src/model/calculate.py) — весь расчёт формулами
из прайса.

**2. Нет данных — нет числа.**
Если цены нет в прайсе, в смете появляется строка `УТОЧНИТЬ`, а не «примерная» цифра.
Каждое допущение выводится отдельным листом
([`estimate.py`](01-telegram-bot-smeta/src/engine/estimate.py), лист «Допущения»).

**3. Лимиты площадок — часть архитектуры.**
Wildberries отвечает 429 и блокирует за частые запросы. Поэтому все обращения идут через один
клиент с интервалами, ожиданием по `Retry-After` и полной остановкой после серии сбоев —
[`mp_core.py`](02-marketplace-analytics/src/mp_core.py) и [`лимиты.py`](02-marketplace-analytics/src/лимиты.py).

## Что здесь сознательно отсутствует

Репозиторий — витрина кода, а не дамп рабочей папки. Из него убрано:

- ключи, токены и пароли (все секреты читаются из переменных окружения и `.env`);
- клиентские данные: заказы, отзывы покупателей, цены поставщиков, переписка;
- фотографии изделий и объектов заказчиков.

Поэтому часть модулей ссылается на файлы-данные, которых в репозитории нет — это нормально
для витрины: логика работы от них не зависит.
